## ConfigMaps

ConfigMaps store non-sensitive configuration data.

### Creating ConfigMaps

```bash
# From literal values
kubectl create configmap app-config \
  --from-literal=DATABASE_URL=postgres://db:5432 \
  --from-literal=LOG_LEVEL=info

# From file
kubectl create configmap nginx-config \
  --from-file=nginx.conf

# From directory
kubectl create configmap app-files \
  --from-file=config/
```

### YAML Definition

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DATABASE_URL: "postgres://db:5432/app"
  LOG_LEVEL: "debug"
  APP_CONFIG.JSON: |
    {
      "featureFlag": true,
      "maxRetries": 3
    }
```

### Using ConfigMaps

```yaml
spec:
  containers:
  - name: app
    image: my-app
    envFrom:
    - configMapRef:
        name: app-config
    env:
    - name: SPECIAL_KEY
      valueFrom:
        configMapKeyRef:
          name: special-config
          key: special.value
    volumeMounts:
    - name: config
      mountPath: /etc/config
```

## Secrets

Secrets store sensitive data (base64 encoded).

### Creating Secrets

```bash
# From literal values
kubectl create secret generic db-credentials \
  --from-literal=username=admin \
  --from-literal=password=secret123

# From file
kubectl create secret tls tls-cert \
  --cert=tls.crt --key=tls.key

# From env file
kubectl create secret generic env-secrets \
  --from-env-file=.env
```

### YAML Definition

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-credentials
type: Opaque
data:
  username: YWRtaW4=  # echo -n "admin" | base64
  password: c2VjcmV0MTIz  # echo -n "secret123" | base64
```

### Using Secrets

```yaml
spec:
  containers:
  - name: app
    image: my-app
    env:
    - name: DB_USER
      valueFrom:
        secretKeyRef:
          name: db-credentials
          key: username
    - name: DB_PASS
      valueFrom:
        secretKeyRef:
          name: db-credentials
          key: password
    volumeMounts:
    - name: certs
      mountPath: /etc/certs
      readOnly: true
  volumes:
  - name: certs
    secret:
      secretName: tls-cert
```

## External Secrets Operator

### Installing

```bash
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets external-secrets/external-secrets
```

### Using External Secrets

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: aws-secrets
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: SecretStore
  target:
    name: aws-secret
  data:
  - secretKey: API_KEY
    remoteRef:
      key: production/api-keys
      property: api_key
```

## Best Practices

### Secret Encryption at Rest

```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
- resources:
  - secrets
  providers:
  - aescbc:
      keys:
      - name: key1
        secret: c2VjcmV0c2VjcmV0c2VjcmV0
  - identity: {}
```

### RBAC for Secrets

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: secret-reader
rules:
- apiGroups: [""]
  resources: ["secrets"]
  verbs: ["get", "list"]
```

## Configuration Patterns

### Environment-Based Config

```yaml
# deployment.yaml
spec:
  containers:
  - name: app
    env:
    - name: NODE_ENV
      value: "production"
    - name: FEATURE_X
      value: "true"
```

### Feature Flags

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: feature-flags
data:
  ENABLE_BETA: "true"
  ENABLE_EXPERIMENTAL: "false"
```

## Secret Rotation

### Automated Rotation with External Secrets

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: rotating-secret
spec:
  refreshInterval: 5m
  secretStoreRef:
    name: vault
    kind: SecretStore
  target:
    name: rotated-secret
    creationPolicy: Owner
  data:
  - secretKey: password
    remoteRef:
      key: database/credentials
      property: password
```
